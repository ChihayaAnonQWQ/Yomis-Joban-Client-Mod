# 像素化与点阵屏 —— 资源包作者指南

[English](pixelation-guide.md)

这份文档写给写 `.js` 预设和配套 JSON 的人。它说明像素化设置**写在哪里**、每个数字**管什么**、
以及**哪组数字对应哪种观感**。

---

## 1. 模组拿到你的面板之后做了什么

当预设要求像素化时，模组不再直接画到方块上，而是：

1. 把整块面板画进一张小的离屏图；
2. 把这张图放大铺回面板。

第一步决定**分辨率**，第二步决定**点**。这是**两个不同的数字**，因为一块真实的板子上本来就有
两样东西：画面，和一组灯珠。每颗灯珠显示一个值，取自它背后的那一整片区域。

| | 决定什么 | 键名 |
|---|---|---|
| **画面分辨率** | 面板画得多细——文字是平滑还是块状 | `pixelScale`、`pixelResolution` |
| **灯珠网格** | 你实际看到多少颗点，每颗多大 | `pixelDots` |
| **点的形状** | 一颗点是方块还是一颗圆灯珠 | `pixelShape` |

**全部不写 = 什么都不变**：面板照旧直接画在方块上，和这个功能出现之前完全一样。

## 2. 写在哪里

模组本来就会读你预设的那个文件：

```
assets/jsblock/joban_custom_resources.json
```

里面有两个位置，可以只用其中一个，也可以两个都用。

### 2a. 整包一次 —— 顶层

```json
{
  "pixelation": {
    "enabled": true,
    "scale": 4,
    "resolution": [272, 152],
    "dots": [68, 38],
    "shape": "circle"
  },
  "pids_images": [ ... ]
}
```

| 键 | 取值 | 含义 |
|---|---|---|
| `enabled` | `true` / `false` | 你的预设要不要像素化。这是以前**没法说**的一件事：预设只要写了 `pixelScale`，不管包愿不愿意都会被像素化 |
| `scale` | `2` … `8` | 默认**除数**。写 `3` 表示面板按三分之一宽渲染。除数的局限是只能落在能整除画布的网格上 |
| `resolution` | `96`、`[96, 54]`、`{"width": 96, "height": 54}` | 默认网格用**多少点**表示。比 `scale` 精确 |
| `dots` | 同上三种写法 | **灯珠网格**——当它比画面粗的时候用 |
| `shape` | `"square"` / `"circle"` | `square` 是 LCD，`circle` 是点阵板 |

### 2b. 逐个预设 —— 写在 `pids_images` 的条目里

```json
"pids_images": [
  {
    "id": "my_crt_board",
    "name": "CRT PIDS",
    "pixelScale": 4,
    "pixelResolution": [272, 152],
    "pixelDots": [68, 38],
    "pixelShape": "circle",
    "scriptFiles": ["mypack:pids/script/my_board.js"]
  }
]
```

逐预设的设置**压过**整包设置。这里的 `id` 就是玩家和客户端配置用的那个 id，起个看得懂的名字。

### 2c. 玩家可以覆盖全部

`config/jsclient.json`，按预设 id 索引：

```json
{
  "pixelScaleByPreset":      { "my_crt_board": 4 },
  "pixelResolutionByPreset": { "my_crt_board": [272, 152] },
  "pixelDotsByPreset":       { "my_crt_board": [68, 38] },
  "pixelShapeByPreset":      { "my_crt_board": "circle" },
  "pixelShapeDefault":       "square"
}
```

**玩家永远优先**，包括他写 `1` 表示"我不想要"——这就是他否决某个包要求的方式。你按你的美术
当初是按哪块屏画的来声明就好，剩下的交给玩家；这既拦不住，也不需要拦。

## 3. 比例永远是画布的

放大后的画面是**被拉伸铺满整块面板**的，所以网格比例和画布不一致就会被**压扁**。为了让这件事
不可能发生，模组把你的**宽度当作意图**，高度按画布重算：136×76 的画布上写 `"pixelResolution": 96`
得到 96×54；写 `[96, 50]` 也会得到 96×54，并在日志里说明原因。

三种画布，以及能落在**精确比例**上的宽度：

| 画布 | 哪些 PIDS | 比例 | 精确的宽度 |
|---|---|---|---|
| **136 × 76** | RV PIDS、两块 SIL 斜面、PIDS 投影仪 | **34 : 19** | 34、68、102、136 … |
| **133 × 72** | LCD PIDS | **133 : 72** | 133（只有它，这对数已经最简）|
| **186 × 60** | 1A PIDS | **31 : 10** | 31、62、93、124、155、186 |

其它宽度照样能用，高度会四舍五入到最近的整数点，误差最多半格。如果你想让网格和脚本自己的坐标
严格对齐，就取上表中间的倍数。

## 4. 怎么选数字

### 一颗点在屏幕上有多大？

这一条决定你的板子**到底像不像点阵**。一块面板大约两格宽，在 1080p、正常视距下大约是
**200 个屏幕像素**。于是：

| 横向多少点 | 每颗点占几个屏幕像素 | 看起来 |
|---|---|---|
| 22 | ≈ 9 | 很粗的方块 |
| 34 | ≈ 6 | 清晰的点 |
| **68** | **≈ 3** | **真实地铁 LED 板的手感** |
| 96 | ≈ 2 | 细点，仍数得清 |
| 136 | ≈ 1.5 | 勉强能分辨是点 |
| 1360 | ≈ 0.15 | **完全看不见**，点被平均成一片平色 |

**小于约两个屏幕像素的点，是看不见的**——要这么细的网格等于不要点。这不是模组的限制：
4K 显示器看不出像素点，也是同一个道理。

### 那我到底该写什么

| 你想要 | 写什么 |
|---|---|
| **真实点阵板**：画面细腻、灯珠可见 | `"pixelResolution": [272, 152], "pixelDots": [68, 38], "pixelShape": "circle"` |
| 同上，但更粗 | `"pixelDots": [34, 19]` |
| 块状 LCD，画面和像素一样大 | `"pixelScale": 4, "pixelShape": "square"` |
| 块状画面 + 圆形灯珠（一颗灯珠一个像素的板子）| `"pixelResolution": [68, 38], "pixelShape": "circle"` |
| 平滑文字，完全不要点 | `"pixelResolution": [272, 152]`（或者更大，如 `[1360, 760]`）|
| 什么都不做（默认）| 什么都不写 |

### 一个完整的例子

你的美术是按 68×38 的板子画的，但你希望它的文字像真正的文字，而不是 38 行的方块。脚本照常写
（它仍然以画布坐标思考），然后声明：

```json
{
  "id": "my_board",
  "pixelResolution": [272, 152],
  "pixelDots": [68, 38],
  "pixelShape": "circle"
}
```

面板按 272×152 渲染，每颗灯珠取它背后 4×4 像素的平均色，圆形遮罩再把每颗灯珠变成圆点。真实
的灰度 LED 板就是这么工作的。

## 5. 代价

- 每个（画布尺寸, 网格）组合一张离屏帧缓冲，**同一组合的所有面板共用**，直到资源包重载才回收。
  272×152 的一张是 165 KB。
- 每块面板多一个 quad（点阵遮罩）；只有**网格比画布更细**时，才会每帧多做一次 mipmap，避免缩小
  采样时闪烁。
- 什么都不声明的预设：**零开销**。

---

## 6. 容易踩的地方

**画布有透明区域 + `"circle"`。** 点与点之间的缝是照着遮罩画的，不把目标读回 CPU 就拿不到逐像素
alpha。铺满背景的预设（几乎所有——第一行就是
`Texture.create("Background").size(pids.width, pids.height)`）没问题；画布留空的预设会在那片区域
得到黑色网点。这种预设请用 `"square"`，或者把背景铺上。

**旧版本的模组会忽略这一切。** `joban_custom_resources.json` 里不认识的键会被跳过，所以声明了
像素化的包在没听过这个功能的老版本上**照样能加载**。这是有意为之：它属于**画面属性**，不是脚本
API，不该让老 jar 加载失败。

**看日志。** 每个发生像素化的预设会打印一次：

```
[PIDS pixelation] preset=my_board scale=1 (declared grid 272x152) shape=circle dots=68x38
                  target=272x152 drawCalls=11 centrePixel=18,149,149,255 glError=0x0
```

`dots=` 是你实际会看到的点数，`target=` 是画面渲染的分辨率，`centrePixel` 说明离屏那一趟确实画进了
东西。如果你写的网格和日志里的不一致，日志也会说明原因：

```
[PIDS pixelation] A resolution of 96x50 does not keep the canvas's 136x76 proportions;
                  using 96x54 so the panel is not stretched. Reported once.
```

**脚本抛错的预设照样会被像素化。** 离屏那一趟会用占位班次重试一次（和直接渲染路径同样的救场），
并在日志里说明。如果你的预设每帧第一次必定抛错，请修预设——重试是安全网，不是替代品。
